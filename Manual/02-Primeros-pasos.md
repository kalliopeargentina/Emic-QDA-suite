# Primeros pasos

## Objetivo
Dejar el entorno listo para trabajar y entender los **objetos núcleo** de un QDA: datafiles, códigos/codebook, dominios/ontología, extracciones y reportes.

## Checklist (primera sesión, ~15–30 min)

1. **Abrí el vault** que usa EMIC Plus QDA y ubicá las carpetas grandes del proyecto (ver [[01-Interfase-de-usuario]]).
2. Confirmá plugins en **Settings → Community plugins** (al menos **Emic‑QDA** y los que necesites para flujos: reportes, tablas, gráficos, cámara, PDF).
3. Leé el orden del proceso en [[03-Flujos-de-trabajo/00-Mapa-de-flujos]].

## Etapa 0 — Configurar el proyecto QDA (estilo ATLAS.ti / NVivo)

### 1) Carpetas en Settings del plugin núcleo
Abrí **Settings** y encontrá las secciones del plugin principal de QDA (Emic‑QDA). Desde ahí podés configurar (nombres orientativos; los verás etiquetados en la UI):

| Área típica | Para qué |
|-------------|----------|
| **Coding / Codes** | Dónde viven carpetas/listado de código y el **storage** del codebook. |
| **Extraction / Extractions** | Carpeta de notas `.md` de extracciones y raíz de almacén de tipos. |
| **Entity / Ontología** | Carpeta visible de **Entidades/Dominios** en el árbol y raíz de ontología/dominios. |
| **Data / Memos / Analysis** | Rutas relativas dentro del vault para fuentes primarias y seguimiento. |

Conviene que coincidan con la estructura que ya mostrás en la barra lateral (*Datos*, *Códigos*, *Extracciones*, *Entidades*).

### 2) Convenciones mínimas de trabajo

- **Datafile**: cualquier **nota-fuente** donde vas a **codificar** y **extraer** (por ejemplo una nota bajo `Datos/Documentos` o tu carpeta estándar).
- **Nombres de archivo**: fecha + tema (`YYYY-MM-DD …`) ordena mejor el archivo.
- **Propiedades** (frontmatter) si tu plantilla las usa: `date`, ubicación/geo, tipo de fuente, actores, `read`/`tags`, etc.
